# Vector Shotcraft

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Cards: 157](https://img.shields.io/badge/shot%20cards-157-blue.svg)](references/cards-index.md)
[![Source: Apache-2.0](https://img.shields.io/badge/upstream-Apache--2.0-orange.svg)](NOTICE.md)

Прикладная библиотека для продуктовых роликов: **157 карточек кинематографичных
приёмов** с точными параметрами (кадры, кривые ускорения, точки-якоря, известные
подводные камни) в **10 функциональных категориях**, плюс два слоя, которых нет
у источника — **методика монтажа по сетке битов** с рабочим инструментом и
тестами и **категорийный словарь звукового дизайна** (16 категорий).

Не готовый конвейер и не библиотека компонентов. Это то, что обычно дороже
всего достаётся: накопленные числа и приёмы — сколько длится наезд камеры,
какую кривую взять на возврат, где приём ломается.

## Быстрый старт

### Посмотреть приёмы

```bash
cd vector-shotcraft
# русский индекс — с него и начинать
less references/cards-index.md

# полный текст конкретного приёма (параметры в кадрах, подводные камни)
less references/cards/camera/crash-zoom-punch.md
```

### Построить сетку битов под свой BGM

```bash
# окружение (нужен питон + librosa)
uv venv ~/.venvs/shotcraft && uv pip install --python ~/.venvs/shotcraft/bin/python \
  librosa soundfile numpy scipy

# сетка: BPM, фаза, допуск, готовый список кадров + JSON
~/.venvs/shotcraft/bin/python scripts/beat_grid.py bgm.mp3 --fps 30 --json grid.json

# проверка самого инструмента на синтетике с известным темпом
~/.venvs/shotcraft/bin/python tests/test_beat_grid.py
```

Вывод читается так:

```
BPM: 129.9978   T(бит): 0.4615462 с = 13.85 кадра
OK   сетка равномерная: остаток по инлайнерам ±8.0 мс (медиана 2.1 мс) <= 15 мс
OK   半/双倍 не нужен: базовая сетка точнее половинной и двойной
INFO сильных ударов в сетке (±17 мс = полкадра @ 30 fps): 12/61 = 19.7%
кадры (первый бит = 0): 21, 35, 49, 63, 77, 90, 104, ...
```

Кадры из этого списка и есть точки для склеек и ударных движений.

### Проверки перед коммитом

```bash
python3 scripts/validate.py
~/.venvs/shotcraft/bin/python tests/test_beat_grid.py
```

То же выполняет CI: `.github/workflows/validate.yml`.

## Ключевые решения

- **Числа важнее гладкости перевода.** Карточки лежат на языке оригинала
  (спецификации с кадрами, эластикой и CSS-свойствами); машинный перевод такие
  числа «улучшает» и ломает. Русский слой — отдельный индекс: что приём делает
  и когда его брать. Апстримный текст защищён валидатором по SHA1.
- **Сетку битов строим робастно, а не по скаляру tempo.** Скалярный BPM врёт на
  проценты, а бит-трекер теряет и удваивает удары. Период ищется методом PDM по
  фазовому пику, фаза — медианой сдвигов, индекс бита — арифметикой, а не
  позицией в массиве, и только потом два прохода отсева и МНК. На синтетике с
  известным темпом остаток укладывается в 15 мс на 120 секундах.
- **Кадры считаются один раз, в самом конце.** Округление каждого шага сетки до
  целого кадра даёт дрейф до 38 кадров к концу двухминутного трека; инструмент
  печатает эту цифру, чтобы её не забыли.
- **Аудиофайлы не переносятся.** Категории — это знание, файлы — лицензии и вес.
  Словарь говорит, что искать и где; у 6 файлов апстрима источник не установлен,
  и это отдельная строка риска.
- **Приёмы — не готовый код.** Библиотека говорит, что и с какими параметрами;
  реализация пишется под свой стек. Так устроен и источник.

## Границы

- Тяжёлые приёмы (crash zoom, dolly-zoom, взрыв-схема, пикирование) — не больше
  1–2 раз на ролик; это ограничение из карточек, не рекомендация.
- Приёмы разобраны с чужих опубликованных промо-роликов: взято только
  ремесло (тайминги, эластика, компоновка), реализации переписаны, брендовых
  элементов нет. Подробности и практический вывод — в `NOTICE.md`.
- Источник предполагает Remotion. **У Remotion своя лицензия**: физлицам и
  малым командам бесплатно, крупным компаниям нужна платная. Приёмы переносимы
  в любой стек — это тайминги и кривые, а не API.
